Seven outcomes, not process data

Users don't care about version graphs. They care that things just work:

1

Duplicates disappear

Identical content keeps one best copy; extras are quarantined — never hard-deleted — and restorable in one click.

2

Files classify themselves

Every file gets a category and an importance class: protected, keep, or ephemeral.

3

Search that finds things

Full-text search over document bodies (SQLite FTS5) — millisecond answers across tens of thousands of files.

4

Important files can't be lost

Protected files are monitored for single-copy risk; one click makes a hash-verified second copy on another location.

5

Junk expires by rule

You switch the rules on; LeanFile executes them — always via quarantine first, always logged, always reversible.

6

Conversations pack for handover

One click bundles what a conversation produced — each file's best version — into a clean folder with a manifest.

7

Shards become visible

Part files and sequence splits that are really one whole are detected and listed as groups, ready to be reunited.

✓

A safety contract

Automation never hard-deletes. The last copy of anything, the current version, and finals are untouchable by cleanup rules. Inferred data is labeled inferred — never presented as fact.

Ten everyday messes

Where LeanFile earns its keep — the situations its first user actually lives in:

1

The article with twelve “final” versions

PAINTwelve rounds of AI edits, twelve saves: final, real-final, final-v2… When it's time to send, even you can't say which one counts — and the nightmare is sending the old draft.

FIXExactly one Final, ever. Every earlier take stays one click away in the version line, but “the current version” has only one answer.

2

Video production chaos

PAINA seven-minute film is hundreds of files — drone originals, voice takes a01–a35, renders v1–v9, a stabilized cut, a light cut… Folders can't tell you which one is the film, and hand-picking files for delivery means one missed file ruins the handover.

FIXFiles group themselves by the work session; shards are detected as groups; one click bundles each file's best version into a clean folder with a manifest.

3

Client deliverables

PAINA proposal revised over weeks, with different versions living in chat threads, email and meeting notes. The client asks “did that number change later?” and you need half an hour to answer safely — while fearing you'll send the internal-discussion version.

FIXOne unambiguous Final, with its source conversation attached. The exported bundle is exactly what the client receives; process versions never slip in.

4

AI pair-programming sprawl

PAINTwo AI coding tools take turns on one project; temp scripts, experiments and generated samples pile up. You dare not commit, dare not delete, and nobody can say which files are the real code.

FIXProcess files are classed ephemeral and expire by rule into a restorable quarantine; real code stays classified and full-text searchable.

5

Data-analysis runs

PAINOne analysis exports forty CSVs and charts, all named data_final(3).xlsx. Three days later, reusing one table means opening every file by hand.

FIXSpreadsheets classify themselves; full-text search finds the table by what's in it; duplicate exports dedup automatically.

6

The book manuscript

PAINChapters polished by AI dozens of times, a dozen versions of each scattered across folders. When the editor asks for the latest chapter, you guess from memory and timestamps.

FIXEvery chapter's version chain stays legible; any chapter's latest draft packs in one click; the submitted draft becomes the one Final.

7

Bid & proposal war-room

PAINDozens of attachments, many hands, a hard deadline. Two fears dominate: submitting something that isn't the final version, and a key attachment existing on exactly one laptop whose disk is about to die.

FIXOne Final per document; single-copy important files raise an alarm and get a hash-verified second copy in one click.

8

AI image batches

PAINOne prompt, twenty images, all named image_4839.png. Picking in Finder is roulette, and afterwards the folder is full of duplicates and rejects.

FIXA preview-thumbnail grid shows all of them at once; pick the Final in place; duplicates merge automatically, rejects expire by rule.

9

Family media vault

PAINA decade of photos and drone footage across a laptop, a desktop and a NAS: the same content stored three times over — while the irreplaceable originals exist exactly once. One dead disk is the family archive gone.

FIXOne registry sees all three locations; byte-level dedup frees space; irreplaceable originals are classed protected and get verified second copies.

10

The 3 a.m. “where is that file?”

PAINOn deadline at 3 a.m. you remember an AI wrote the perfect paragraph — or built the perfect table — in some chat last month. You remember roughly what it said, never what it's called. Filename search finds nothing; chat history swallows the evening.

FIXSearch by what the file says, or open the conversation that made it and see everything it produced. Milliseconds, not an evening of digging.

Organized by conversation

You remember a file by the chat that produced it — not by its folder.

LeanFile organizes files under the LLM conversation or work session that created them. Registrations carry conversation metadata (tool, model, title); legacy files are reconstructed into sessions by project folder + time-window analysis — honestly labeled inferred.

The macOS app opens on a dashboard: totals, capacity, category and type breakdowns, production by day. Click any number and the matching files are right there — as a list, or as a preview-thumbnail grid.

How it's built

A platform-independent engine, a native shell, and compute that stays local first.

Core engine · Python

Content-hash identity (SHA-256), sidecar manifest protocol, version chains, state machine, dedup, near-duplicate clustering, FTS5 indexing, storage-node replication, autopilot rules.

macOS app · SwiftUI

Resident, launch-at-login, Finder-companion UI on the same SQLite registry. All database work runs off the main thread. UI follows your system language.

Compute tiers

Local algorithms first, local models or your own endpoints next, optional official cloud last — every run records which tier did the work and what it cost.

Open core, honestly

The local core is open source under Apache 2.0 — full-featured, forever. The official cloud is an optional add-on for people without local compute: hosted processing, sync & backup, team collaboration. Your files stay exportable, stopping payment never touches your assets, and cloud processing never trains on your data.

Quick start

The engine is a Python CLI today; the macOS app builds with only the Command Line Tools.

python3 -m mm1031.cli --db leanfile.db node-add mac ~/Documents --kind local
python3 -m mm1031.cli --db leanfile.db scan mac
python3 -m mm1031.cli --db leanfile.db build-previews
python3 -m mm1031.cli --db leanfile.db conversations      # files by conversation
python3 -m mm1031.cli --db leanfile.db bundle --latest    # pack for handover
python3 -m mm1031.cli --db leanfile.db protect-run --yes  # back up the important ones

# macOS app
cd macos && ./build.sh && open build/LeanFile.app

Download the installer (.pkg)
