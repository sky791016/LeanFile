# 归藏原生应用架构（macOS 常驻 · Finder 增强层）

产品形态（Sky 2026-10-22 定）：不是独立文档库，而是常驻内存、开机自启、在 Finder 之上工作的增强层。参考 FSearch/Everything 的索引哲学：索引先行、常驻更新、搜索边打字边出结果；归藏在其上叠加三层：大模型产物的版本管理、去重、全文检索。

## 进程结构（两个进程，各司其职）

1. Guicang.app（SwiftUI）：主窗口 + 菜单栏常驻（MenuBarExtra）。负责一切人机交互：即时搜索、收件箱拍板、版本浏览与恢复、去重确认、覆盖率报告。关窗不退出，索引与守护由下面的进程负责。
2. GuicangHelper（LaunchAgent 守护进程，无界面）：开机自启（SMAppService 注册 / LaunchAgent），常驻内存。负责：
   - FSEvents 监听登记目录的增删改（带防抖与背压队列），实时维护索引——FSearch 式「索引永远是最新的」
   - 版本捕获：受管文件变更时，把旧版以 APFS 克隆（clonefile，写时复制，近乎零空间）存入内容寻址版本库，再登记新版；版本不再靠改文件名
   - 内容抽取与全文索引（FTS5）：文本直读，PDF/Office 在 Mac 上走 PDFKit/textutil/Spotlight 导入器
   - 哈希与指纹计算队列（低优先级 QoS，不抢前台性能）
   - 内存驻留热索引：文件名/路径索引常驻 RAM（mmap + 内存结构），百万级文件搜索目标 <50ms

## 与 Finder 的关系（增强，不替代）

- 文件留在原地：归藏不接管目录结构，Finder 里一切照旧
- Finder Sync 扩展（二期）：受管文件加状态徽标（草稿/候选/金印定稿），右键菜单「登记到归藏 / 晋升定稿 / 查看版本线」
- Quick Look 插件（二期）：空格预览时显示版本数与来历
- 时间机器式版本浏览器：选中文件，从归藏里按时间轴恢复任意旧版（数据源是 APFS 克隆版本库，与 Time Machine 互补：它管整盘备份，归藏管单文件的语义版本）

## 数据层（与 Python 原型同协议）

- 登记库 SQLite（WAL）：assets / versions / blobs / locations / provenance / enrichments
- 全文：FTS5 虚表（内容）+ 名称索引（内存）
- 指纹：指纹表（SimHash/感知哈希），归并结果 frag_clusters
- 全部本地，用户可整体导出（开源承诺）

## 性能目标（对标 FSearch 的手感）

- 常驻内存：守护进程空闲 <150MB（不含可选本地模型）
- 搜索：百万文件内名称搜索 <50ms，边打字边刷新
- 摄入：变更感知延迟 <2 秒；批量扫描沿用引擎实测（万级文件/秒）
- 版本捕获：APFS 克隆使单次留版成本 ≈ 一次元数据操作，不复制数据本体
